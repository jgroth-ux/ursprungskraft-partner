### T14 – Datenstruktur für Automatisierung

Bei programmgesteuerter Verarbeitung ist ein maschinenlesbares Objekt hilfreich. Beispiel für ein **illustratives** Schema; Pflicht- und optionale Felder projektseitig spezifizieren:

```json
{
  "brief": {
    "product": "Fiktive Angebotssoftware",
    "audience": "Kleine Service-Teams",
    "awareness": "problem-aware",
    "temperature": "cold",
    "objective": "qualified_demo",
    "primary_cta": "Demo ansehen"
  },
  "truth": {
    "supported_claims": [
      "Angebote und Status in einer Ansicht"
    ],
    "unsupported_claims": [
      "Garantierte Umsatzsteigerung"
    ]
  },
  "angle": {
    "buyer_trigger": "Angebot in Nachrichten nicht auffindbar",
    "old_belief": "Das Team muss sich besser organisieren",
    "new_belief": "Ein gemeinsamer Status reduziert Suchaufwand im Prozess",
    "mechanism": "Zentrale Vorgangsübersicht"
  },
  "creative": {
    "hook": "Wo ist dieses Angebot gelandet?",
    "body": "Zeige verstreute Nachrichten und die zentrale Übersicht.",
    "proof": "Produktdemo",
    "cta": "Demo ansehen"
  },
  "quality": {
    "claims_verified": false,
    "needs_approval": [
      "Produktfunktionen im realen Build validieren"
    ]
  }
}
```

**Validierungsregel:** Sobald `claims_verified` nicht ausdrücklich `true` ist, darf das System keine Veröffentlichung als vollständig freigegeben kennzeichnen.
